# 0008. Home のリデザイン — 「観察ノート」モチーフでプロダクトを前に出す

- 状態: Accepted
- 日付: 2026-09-22

## 背景

Home（`/`・`/en/`）は「見出し＋テキストカード 3 枚」の文書レイアウトで、規約置き場としては
十分だがプロダクトの魅力が伝わらない。参考にした個人開発者サイト（path-biz.com）は
1 プロダクト 1 大セクション・スクショ主役・統一モチーフ（空港）・スクロール演出で構成されており、
同じ方向へ寄せたい。素材はストア用スクショ（各アプリ ja/en・端末フレームなしの raw）が揃っている。

## 決定

### 世界観
- **暖色クリームの紙を基調にした「観察ノート（フィールドノート）」**。サイト全体を 1 冊のノートと
  見立て、Hero = 表紙、各プロダクト = 1 見開き（spread）、Blog/X = 巻末メモとする。
- アクセントとして **スクロール進捗の代わりに小さなカメが歩く**（ヘッダー直下の細いトラック）。
  遊びはこの 1 箇所だけに限定する。

### デザイントークン（BaseLayout `:root`）
- 紙: `--bg: #fbf7ee`（既存）／`--paper-2: #f4eddc`（見開きの地）／罫線 `--rule: rgba(65,89,45,.10)`
- 文字: `--fg: #2c2c2c`・`--muted: #6b6b6b`・`--brand: #41592d`（既存）
- アプリ固有色（アクセント / 淡色地）:
  - こうら日記 `--acc-koura: #5f8a3c` / `--tint-koura: #e9f0dc`
  - Schemely `--acc-schemely: #2b8f6f` / `--tint-schemely: #dff4ec`
  - カメコロ `--acc-kamekoro: #c9731f` / `--tint-kamekoro: #fdefcf`
  - 文字に使うときはクリーム地に対してコントラスト 4.5:1 以上を満たすこと（上の値は満たす）
- フォント: Inter（見出し・英字・800）＋ Noto Sans JP（本文）。手書き風ラベルにのみ
  **Zen Kurenaido**（Google Fonts）。いずれも `display=swap`・`preconnect` 付き。Lism CSS は当面維持。

### レイアウト
- `BaseLayout` に `width: 'doc' | 'wide'` prop を追加。既定 `doc`（44rem・規約は不変）、Home と
  各アプリ LP は `wide`（72rem）。
- **表紙（Hero）**: 罫線入りの紙の上に、小ラベル「FIELD NOTES / 観察ノート」、巨大な「7ofu」
  （Inter 800・`clamp(4rem, 12vw, 9rem)`）、一行コピー、下端に「ページをめくる ↓」。
- **見開き（Spread）**: 2 カラム（写真 5 : ノート 7）、偶数番目は左右反転。
  - 写真側: スクショを白フチ 8px の「写真プリント」として置き、±2° 傾け、上角にマスキングテープ
    （アプリ淡色・半透明・疑似要素）を貼る。背景はアプリ淡色地。
  - ノート側: 手書き風ラベル「No.01」、アプリ名＋アイコン、タグライン、標本ラベル風の項目
    （観察対象／生息地（対応 OS）／状態）、特徴 3 点、CTA（App Store 入手 ＋ 詳しく →）。
- **巻末**: Blog（ja のみ）と公式 X を小さなメモとして置く。
- アプリのデータ（名前・アイコン・色・スクショ・コピー・ストア URL）は `src/data/apps.ts` に
  locale 別で一元化し、Home とアプリ LP の Hero（同じ Spread コンポーネント）で共用する。

### 演出
- 見開きは IntersectionObserver で `.is-in` を付与し、CSS で出現（不透明度・18px 上昇・傾きの補正、
  600ms）。**JS 無効時は最初から表示**（`html.js` が付いたときだけ初期非表示）。
- `prefers-reduced-motion: reduce` では出現アニメを無効化し、カメは位置更新のみ（脚の動きなし）。
- カメの歩行: `scroll` を rAF で間引き、進捗を `--progress` として track に渡す。Home のみ。

### 変更しないもの
- DocLayout・`.md` 規約／ヘルプ／ブログ本文。問い合わせフォーム。i18n の仕組み（adr/0004・0007）。

## 理由

- **観察ノート**は 3 アプリ全部に無理なく当てはまる（Schemely も「実験ノート」）。既存の
  クリーム基調・ブログの「メモ」トーンと地続きで、ペット系アプリ 2/3 の温度感にも合う。
  代替の「爬虫類館」は Schemely が浮き、「甲羅の成長線」は物語が弱かった。
- スクショは raw（端末フレームなし）を使い、ストア用の合成画像（キャッチコピー焼き込み）は使わない。
  コピーはサイト側で持ち、写真プリントとして統一的に見せられるため。カメコロだけは raw に画面録画の
  インジケータが写るためストア用合成画像をゲーム枠で切り抜いて使う。
- データを `apps.ts` に寄せるのは、Home と LP でコピー・URL・状態バッジがずれる事故を防ぐため。
- 演出は CSS 主体・JS 数十行に留め、フレームワーク追加はしない（Astro 静的・ゼロ依存を維持）。

## 代替案

- **path-biz と同じ白×寒色クリーン**: アプリの世界観（暖色・かわいい）と離れるため不採用。
- **アニメーションライブラリ（GSAP 等）導入**: 依存と JS 量が増える。IntersectionObserver で十分。
- **ストア用合成画像をそのまま使う**: 手早いがキャッチコピーが二重になり、写真プリントの見立てが崩れる。

## 影響

- `public/shots/<app>/<lang>-<name>.webp`（幅 640）を追加。元画像は各アプリ repo の
  `screenshots/raw`（カメコロは `docs/store/screenshots`）。差し替え時は `cwebp -q 82 -resize 640 0`。
- Home（ja/en）・3 アプリ LP（ja/en）の Hero が変わる。規約ページの見た目は変わらない。
- 新しい UI 部品（Spread・カメ）を足すときはこの ADR のトークン・演出条件に従う。

## 追記（2026-09-22・レビュー反映）

- 「決定」に書いたアクセント色は WCAG 相対輝度で実測すると 4.5:1 未満だった
  （koura 3.79 / schemely 3.73 / kamekoro 3.30 対 `--bg`）。文字・ボタン地に使うため一段暗くする:
  - `--acc-koura: #4a7029`（5.39:1）／`--acc-schemely: #1f7358`（5.38:1）／`--acc-kamekoro: #9c5412`（5.32:1）。
    白文字を載せたボタン地としても 5.7:1 前後。淡色地（`--tint-*`）は変更なし。
- Spread をアプリ LP の Hero として使うときはアプリ名を `<h1>`、Home の一覧では `<h2>` にする
  （各ページの h1 は 1 つ）。
- Home の見開きに載せる写真は **最大 2 枚**（3 枚だと 5fr 側が縦に伸びて見開きの均衡が崩れる）。
  LP の Hero では用意した全枚数を載せる。

## 追記 2（2026-09-22・プレビュー確認のフィードバック）

- **Schemely は Home で見開きにしない**。開発者向けツールで、一般向けの 2 アプリと同じ粒度で
  並べると主役がぼける。Home は こうら日記（No.01）・カメコロ（No.02）の 2 見開きにし、Schemely は
  巻末の手前に「余白のメモ」（アイコン・一行・開発者向けタグ・App Store／詳しく）として小さく置く。
  Schemely の LP（`/schemely/`）は standalone の見開きのまま。
- **ストアは iOS/Android を配列で持つ**（`stores: { ios?: url; android?: url }`）。こうら日記は
  Google Play（`com.togawa.tortoise_log`）も公開済みで、CTA を 2 つ並べる。生息地（habitat）の文言は
  導出せず手で書く（iPad 対応や OS 下限など、ストアの有無だけでは決まらないため）。**stores を変えたら
  habitat も同時に見直す。**
- **ヘッダーの重なり**: sticky ヘッダーに `z-index` が無く、見開きの `translate`／写真の `rotate` が作る
  stacking context に負けて下をくぐられていた。ヘッダーに `z-index` を付け、カメのトラックは
  ヘッダーの下端に固定して一緒にスクロール追従させる（スクロール中に進捗が見えなければ意味がない）。
- **LP の下段（使い方／規約・ポリシー／お問い合わせ）は「目次」スタイル**に統一する。白い角丸カードは
  ノートの世界観から外れて汎用テンプレに見えるため、罫線の上に見出し・説明・点線リーダー・矢印を並べる
  `DocIndex` に置き換える（Home の巻末も同じ部品）。セクション見出しは文書用 h2（緑バー）ではなく
  手書き風の小ラベルにする。DocLayout（規約本文）の見出しスタイルは従来どおり。
- **サイト共通のお問い合わせ `/contact`・`/en/contact`** を新設し、nav・フッター・Home 巻末から辿れるようにする。
  種別に「対象アプリ」（こうら日記／Schemely／カメコロ／サイト・その他）を持ち、Web3Forms の subject は
  `7ofu.dev お問い合わせ` で統一する。既存の `/<app>/contact` は **ストア掲載のサポート URL として
  参照されているため残す**（削除・リダイレクトしない）。
